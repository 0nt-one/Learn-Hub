# Learn-Hub 功能需求与业务规则

状态：设计基线 v1，待确认。当前仅交付文档，本文的业务功能均未实现。

## 1. 目标与范围

面向学生、教师和管理员，提供按课程与分类整理学习资源、审核共享资源、记录学习进度和收藏的在线平台。

工程第一阶段仅计划实现工程骨架、九类数据库模型、健康检查和首页联调。身份认证、资源管理等按后续阶段逐步实现，不能将本需求清单当作当前已交付功能。

为使第一版边界明确，本设计采用以下可调整假设：

- 所有启用课程面向所有已登录用户开放；暂不引入选课、班级、课程成员与付费权限。
- 学生和教师均可共享资源；教师仅审核自己负责课程内其他人提交的资源，管理员可跨课程审核，但任何人均不可审核自己的资源。
- 第一版资源以外部 HTTPS 链接登记，支持文档、视频和普通链接；不上传文件、不代理下载、不由服务端抓取远程地址。
- 分类为单层结构；每个资源必须归属一个课程和一个分类。
- 暂不支持评论、评分、全文检索、推荐算法、邮件推送和多租户。

## 2. 功能需求

| 编号 | 功能 | 验收行为 |
| --- | --- | --- |
| F01 | 注册、登录与当前用户 | 自助注册只能创建学生；登录签发短期令牌；停用用户无法登录或继续访问受保护接口 |
| F02 | 用户管理 | 管理员查看用户、修改角色和启停账户；保留至少一个启用管理员 |
| F03 | 课程管理 | 教师创建并维护自己的课程；管理员可管理全部课程；负责人只能为启用教师 |
| F04 | 分类管理 | 管理员维护唯一分类名称和启用状态；登录用户查看启用分类 |
| F05 | 资源管理 | 学生和教师创建草稿、修改本人草稿或被拒资源、提交和撤回；管理员可归档违规资源 |
| F06 | 资源发现 | 按标题关键词、课程、分类、类型筛选和分页；普通目录仅展示已通过且课程、分类启用的资源 |
| F07 | 资源审核 | 教师或管理员查看授权审核队列，通过或拒绝；记录审核人、意见、结果和被审核版本 |
| F08 | 学习记录 | 用户查看并更新自己的资源进度；同一用户与资源仅一条当前进度 |
| F09 | 收藏 | 用户收藏可见资源、取消收藏和查看自己的收藏；重复收藏不会产生重复数据 |
| F10 | 站内通知 | 审核结果在同一事务内产生通知；用户只可读取及标记自己的通知 |
| F11 | 操作日志 | 记录资源提交/审核/归档和用户、课程、分类管理操作；仅管理员查询 |
| F12 | 健康检查 | 首页请求后端并显示成功、失败与重试；后端检查数据库连通性及预期表是否存在 |

## 3. 权限矩阵

“本人”通过数据库中的 owner_id / user_id 与令牌对应用户比较；“负责课程”通过 courses.teacher_id 判断。

| 操作 | 学生 | 教师 | 管理员 |
| --- | --- | --- | --- |
| 浏览公开目录和资源详情 | 可 | 可 | 可 |
| 创建、编辑、提交本人资源 | 可 | 可 | 不创建资源 |
| 查看本人非公开资源 | 可 | 可 | 可查看全部以履行管理职责 |
| 创建课程 | 否 | 可 | 可指定教师创建 |
| 修改或停用课程 | 否 | 仅负责课程 | 全部 |
| 管理分类、账户与角色 | 否 | 否 | 可 |
| 查看待审核资源并审核 | 否 | 仅负责课程，排除本人资源 | 全部，排除本人资源 |
| 撤回本人资源、归档本人非待审资源 | 可 | 可 | 可归档全部资源 |
| 学习进度、收藏、通知 | 仅本人 | 仅本人 | 仅本人 |
| 查询操作日志 | 否 | 否 | 可 |

管理员可能因历史角色变更而拥有资源，因此仍需执行禁止自审规则。管理员无权通过通用用户更新接口读取或修改他人的密码。

所有权限在后端逐次验证。前端隐藏按钮只改善交互，不能形成授权依据。禁止信任请求传入的 owner_id、reviewer_id、user_id、角色或资源状态。

## 4. 核心业务规则

### 4.1 账户与身份

- 用户名限定 ASCII 字母、数字和下划线，3–32 字符；去首尾空格并转小写后存储，数据库大小写不敏感唯一约束兜底。
- 密码长度 12–128 字符，使用 Argon2id 哈希，不存明文、不写入日志；响应不包含 password_hash。
- 身份使用 Bearer JWT，计划有效期 30 分钟；后端校验签名、算法白名单、过期时间、签发者、受众，并查询数据库中的当前角色及启用状态。密钥从环境配置读取，缺少密钥时未来认证模块应拒绝启动。
- 第一版不做刷新令牌；退出登录清除前端内存令牌。已有令牌在到期前仍可能有效，需立即撤销访问时停用账户。角色和停用状态以数据库为准。
- 首位管理员由后续受控 CLI 创建；公开注册永远不能指定角色。禁止管理员停用自己或取消自己的管理员角色，防止丢失管理入口。
- 教师被降级或停用前，必须先由管理员转移其负责课程。

### 4.2 资源状态机

| 当前状态 | 动作 | 下一状态 | 前提 |
| --- | --- | --- | --- |
| 无 | 创建 | draft | 学生或教师，课程、分类启用 |
| draft / rejected | 编辑 | 原状态 | 本人；更新内容及版本号 |
| draft / rejected | 提交 | pending | 本人；元数据校验通过，课程、分类启用 |
| pending | 撤回 | draft | 本人；与审核竞争时只能一个成功 |
| pending | 审核通过 | approved | 授权审核人、非本人；课程、分类仍启用 |
| pending | 审核拒绝 | rejected | 授权审核人、非本人；意见必填 |
| approved | 撤回 | draft | 本人；立即从公开目录隐藏 |
| draft / rejected / approved | 归档 | archived | 本人或管理员 |
| pending | 强制归档 | archived | 仅管理员，必须提供原因 |

archived 为终态。已通过资源不得原地编辑；先撤回，再编辑并重新提交。审核记录只追加，不覆盖。资源每次变更 version_id 递增；修改、提交、撤回、审核、归档请求必须携带已读取版本，过期返回 409。

### 4.3 可见性与关联数据

- 常规访问条件：资源 approved，所属课程和分类启用。账户停用不自动删除其已共享资源，管理员可另行归档。
- 本人可在“我的资源”查看其全部状态；教师可在审核入口查看负责课程的 pending 资源；管理员管理入口可查看全部。资源详情也复用同一可见性判定。
- 不可见资源对无权用户返回 404，防止泄露其存在；可见但无操作权限返回 403。
- 停用课程或分类立即隐藏关联资源，并禁止新建、提交和通过审核；已有记录保留。被停用分类不能被新资源引用。
- 收藏和学习进度只允许写入常规可见资源；既有个人列表可显示“资源暂不可用”与资源 ID，但不得暴露非公开标题或链接。取消收藏仍允许。
- 学习进度为 0–100 整数，可回退；100 表示完成；仅保存最新进度和最后学习时间，不声称验证真实观看时长。
- 每个用户对每个资源最多一条收藏和一条学习记录；重复 PUT 收藏幂等成功，重复 DELETE 取消收藏幂等成功。

### 4.4 数据与事务

- 资源仅存外部 URL 与元数据：标题 1–200 字符、描述最多 5000 字符、URL 最多 2048 字符；标题和描述为纯文本。只允许 HTTPS 且无用户名密码的 URL。
- 视频必须提供正整数 duration_seconds；文档可提供正整数 page_count；普通链接不允许两者。元数据仅用于组织资源，不代表已校验远端内容。
- 账号、课程、分类采用停用；资源采用归档，第一版不提供硬删除业务 API，避免破坏审核历史。
- 审核状态变更、审核记录、结果通知和操作日志同一数据库事务提交，任一失败全部回滚。其他写操作与相关操作日志也同事务提交。
- 通知和日志不写令牌、密码或敏感请求体。日志保留操作者外键、动作、目标类型与 ID、时间和脱敏摘要。

## 5. 质量要求与交付边界

- 前端为 Vue 3 + TypeScript + Vite，使用 Vue Router；Nuxt UI 作为组件库接入，不使用 Nuxt 框架、服务端路由或 Nuxt 自动目录约定。
- 后端为 FastAPI + Pydantic 2 + SQLAlchemy 2.x，同步 Session；SQLite 用于单实例起步，每个连接启用外键约束。
- 列表默认每页 20，最大 100；数据库与 API 统一使用 UTC，API 输出 ISO 8601 带 Z，页面按本地时区展示。
- 自动化测试使用 pytest + HTTPX；后续优先覆盖越权、重复数据、非法状态流转与事务回滚。
- 当前只编写设计文档，不宣称依赖安装、样式组件运行、数据库初始化或自动化测试已通过；这些是工程阶段验收项。
