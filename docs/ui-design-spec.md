## 2. 设计原则

- **蓝白科技风**：以白色内容表面、浅蓝页面背景、清晰蓝色操作为基础；科技感来自秩序、细边框、局部渐变和插画，不依赖大面积霓虹、玻璃模糊或深色背景。
- **角色密度不同**：学生首页强调发现与兴趣；资源中心强调比较和筛选；教师强调共享、状态和待办；管理员强调全局概况、审核与操作效率。
- **主任务唯一**：首页先搜索，资源中心先定位资源，教师先共享或处理反馈，管理员先处理待审核。每个局部操作组至多一个实心蓝主按钮。
- **渐进披露**：次要字段、完整审核意见和高级筛选按需展开；管理表格保持可扫描。信息密度靠网格与行高调整，不缩小正文至难读。
- **真实可解释**：零、缺失、失败和未接入分别显示；不把“无统计”显示成 0，不把接口错误显示成空列表。
- **互动可达**：悬停、焦点、选中、加载、禁用、提交成功和失败均有反馈；触屏、键盘操作与鼠标同等完整。
- **统一而不僵化**：共享色彩、字体、按钮、状态和布局壳；首页允许更大圆角和插画，管理端使用更紧凑的卡片与表格。

## 3. 视觉令牌

所有令牌集中在全局主题层；页面引用语义变量，不散落硬编码色值。以下是 Learn-Hub 自有令牌，实施时映射至安装版本的 Nuxt UI 主题入口。

### 3.1 色彩

| 语义 | 值 | 用途 |
| --- | --- | --- |
| `--lh-primary` | `#004CFF` | 主按钮、链接、选中导航、图表主线 |
| `--lh-primary-hover` | `#003DD1` | 主操作悬停 |
| `--lh-primary-pressed` | `#0033AD` | 主操作按下 |
| `--lh-primary-soft` | `#EAF0FF` | 选中项底色、轻提示 |
| `--lh-primary-border` | `#B7C9FF` | 品牌边界、选中组件 |
| `--lh-page` | `#F5F8FF` | 页面背景 |
| `--lh-surface` | `#FFFFFF` | 卡片、顶栏、侧栏、浮层 |
| `--lh-surface-subtle` | `#F1F5FB` | 表头、次级区域、Skeleton 基底 |
| `--lh-text` | `#0B1535` | 主标题、正文 |
| `--lh-text-secondary` | `#52627A` | 说明、元数据、输入提示 |
| `--lh-border` | `#E2E8F2` | 装饰分隔线；不单独承担表单边界 |
| `--lh-control-border` | `#7D8AA0` | 需要清晰识别的输入/复选框边界 |
| success 文本 / 底色 | `#007A53` / `#EAF8F1` | 已发布、通过、成功 |
| warning 文本 / 底色 | `#935400` / `#FFF6E5` | 待审核、需关注 |
| danger 文本 / 底色 | `#B42332` / `#FFF0F2` | 驳回、错误、归档确认警示 |
| neutral 文本 / 底色 | `#52627A` / `#F1F5FB` | 草稿、已归档、不可用 |

白字配主色对比度约 6.04:1；次级文字配白底约 6.20:1。上线前按实际透明度、背景和字号复核。浅边框仅用于装饰，焦点和必要控件轮廓需满足非文本对比度。禁用控件通过语义禁用和说明表达，不仅降低透明度。

渐变仅用于 Hero、专题封面和轻量装饰：浅蓝到白，例 `#EAF4FF → #FFFFFF`。首页专题可用少量紫、绿、橙辅助色，但主按钮始终为品牌蓝。管理端图表使用蓝、青、紫、橙等固定类别映射，并配文字/线型区别。

### 3.2 字体与排版

默认字体：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。不强制下载字体；缺少 Inter 时使用系统字体。数字采用等宽数字特性 `tabular-nums`，不替换中文字体。

| 层级 | 桌面 字号/行高 | 移动 字号/行高 | 字重 |
| --- | --- | --- | --- |
| 学生 Hero 标题 | 48/58 px | 30/40 px | 700 |
| 页面 H1 | 30/40 px | 24/34 px | 700 |
| 区块 H2 | 20/28 px | 18/26 px | 600 |
| 卡片标题 | 16/24 px | 16/24 px | 600 |
| 正文 | 14/22 px，首页说明可 16/26 | 14/22 px | 400 |
| 元数据/辅助说明 | 12/18 px | 12/18 px | 400 |
| 指标数值 | 32/40 px | 28/36 px | 700 |

每页一个 H1，区块用 H2；不能靠粗体模拟标题结构。标题最多两行，摘要最多两行；完整标题在详情中可读，悬停提示仅作补充。金额/访问量等指标展示千位分隔；中文文案不沿用图片中的乱码、拼写和旧日期。

### 3.3 间距、圆角、边界

- 基础间距为 4 px：4、8、12、16、20、24、32、40、48、64；局部不得任意使用不一致的间距。
- 首页区块间距 24–32 px，Bento 内卡片间距 20–24 px；资源中心网格 16–20 px；教师 20–24 px；管理员 16 px。
- 卡片内边距：首页 24 px，资源卡 16 px，教师 20 px，管理员 16 px；移动统一降为 16 px。
- 圆角：输入/按钮 8 px，资源卡与后台卡 12 px，首页 Bento 20 px，Hero 24 px，标签胶囊 999 px。
- 默认 1 px 边框；阴影只在浮层、Hero 或悬停卡片使用。建议基础阴影 `0 4px 20px rgb(15 42 95 / 5%)`，浮层 `0 16px 48px rgb(15 42 95 / 14%)`。
- 图标以同一套线性图标为主，默认 20 px；导航 20–24 px；资源类型 24 px。不混用多套粗细或以 emoji 代替正式导航图标。

### 3.4 操作组件规格

常规按钮/输入高 40 px；首页搜索高 56 px（移动 48 px）；桌面后台紧凑控件可 32–36 px。触屏下实际可点区域至少 44×44 px，可通过外层内边距扩大。主按钮实心蓝、白字；次操作白底边框；低优先级用 ghost；危险操作用 danger 语义，不以品牌蓝掩盖。

焦点统一 2 px 主色轮廓、2 px offset；按钮按下仅轻微颜色变化。图标按钮必须有可访问名称与必要 Tooltip。加载按钮保留原宽度并阻止重复提交。

## 4. 布局、导航与响应式总约定

### 4.1 网格与断点

按 CSS 视口宽度定义：移动 `<768 px`，平板 `768–1023 px`，桌面 `≥1024 px`，宽桌面 `≥1280 px`。桌面视觉基准为 1440×1080，同时验收 1280×800、1024×768、768×1024、390×844 和 320×720；断点附近额外检查 767/768、1023/1024。

学生内容最大宽 1440 px 居中；桌面两侧留白至少 24 px，宽屏可 32 px，平板 24 px、移动 16 px。教师和管理员主内容随视口填充，超宽屏主体最大宽 1760 px 居中，侧栏不随之拉宽。

| 区域 | 桌面 | 平板 | 移动 |
| --- | --- | --- | --- |
| 顶栏 | 高 64 px，主导航展开 | 高 64 px，收起次要导航 | 高 56 px，菜单按钮+品牌+必要动作 |
| 教师/管理员侧栏 | 宽 224/240 px，可折为 72 px 图标栏 | 默认抽屉 | 抽屉，宽 `min(320px, 88vw)` |
| 资源筛选栏 | 宽 240 px，内部可滚动 | “筛选”按钮打开抽屉 | 全屏或底部抽屉，固定底部应用按钮 |
| 内容列数 | 使用各页规则 | 2 列为主 | 单列；指标可 2 列 |

顶栏 sticky，资源筛选栏 sticky 顶部为顶栏高度+16 px。后台使用一个主滚动容器；侧栏菜单独立滚动。移动抽屉锁背景滚动，关闭后恢复位置。表格仅在自身容器横向滚动，整页不得横向溢出。

### 4.2 布局壳与路由建议

| 布局壳 | 路由建议 | 主导航 |
| --- | --- | --- |
| `StudentLayout` | `/`、`/resources` | 发现、资源中心、学习中心、收藏；教师入口按角色显示 |
| `TeacherLayout` | `/teacher` | 工作台、我的资源、共享新资源、审核结果；课程审核按权限独立入口 |
| `AdminLayout` | `/admin` | 首页概览、资源审核、资源管理、用户管理、分类管理、操作日志 |

这些是后续前端路由建议，已有路由存在时先映射再实施，不批量改名。学习中心、详情、共享表单等是四页动作的目标入口，不代表本轮额外实现整套页面；仅在对应阶段授权范围内接入真实目标。未实现目标不显示可点击正式入口，可在演示说明中列出。

学生顶部当前导航用浅蓝底或蓝色下划线；后台侧栏用浅蓝底+蓝色文字+左侧强调线，设置 `aria-current="page"`。可折叠菜单保留 Tooltip 与键盘导航。教师和管理员都用同一品牌标识，加 Teacher/Admin 角色文字，不按角色另造 Logo。

### 4.3 层级与页面行为

层级建议：普通内容 0、sticky 筛选 10、顶栏 20、浮动工具 30、遮罩/抽屉 40–50、Modal 60、Toast 70；通过全局层级配置与 Nuxt UI Portal 协调，不盲目写极高 z-index。

进入新页面将焦点移到主内容标题并从顶部开始；列表进入详情再返回时恢复筛选、页码和滚动位置。抽屉和弹窗采用库的焦点管理；打开聚焦标题或首项，Esc 关闭，关闭恢复触发器。未提交表单离开需确认。

## 5. 通用状态、数据与交互契约

### 5.1 所有异步模块必须覆盖的状态

| 状态 | 界面与操作 |
| --- | --- |
| 初始加载 | 使用与最终结构一致的 Skeleton，保留图片宽高和卡片高度；区域 `aria-busy` |
| 刷新中 | 保留上一份同权限数据与布局，工具条显示刷新反馈；响应完成后更新，不闪空整个页面 |
| 成功 | 使用真实 DTO；可缺字段采用约定占位，不生成随机数 |
| 无内容 | 如“还没有共享资源”，给出该角色可执行的首个动作 |
| 无搜索结果 | 显示关键词/筛选摘要，提供“清空筛选”；不混同首次空数据 |
| 局部失败 | 该卡片显示失败说明与手动重试，其他成功模块继续可用 |
| 全页失败/离线 | 保留导航与输入；说明连接问题、重试、必要 request_id。没有缓存则不显示过时数据 |
| 未接入 | 明确“统计数据暂未接入”等产品说明；不同于错误、0 和空列表 |
| 无权限/资源不可见 | 403 显示无操作权限；404 统一“资源不存在或暂不可用”，不泄露非公开标题和链接 |

加载超过约 200 ms 才显示短操作的 spinner，避免闪烁；没有响应时按 API 客户端的超时策略进入失败，不能无限 Skeleton。初次进入的大列表可立即显示占位。状态说明用中文，错误信息对普通用户可理解，不显示 SQL、堆栈或令牌。

### 5.2 资源、审核与错误语义

| API 值 | 显示名 | 视觉 |
| --- | --- | --- |
| `draft` | 草稿 | neutral |
| `pending` | 待审核 | warning+时钟图标 |
| `approved` | 已发布（资源）/已通过（审核结果） | success+勾图标 |
| `rejected` | 已驳回 | danger+说明入口 |
| `archived` | 已归档 | neutral+归档图标 |

资源操作严格复用现有状态机：仅本人 draft/rejected 可编辑；approved 须先撤回；archived 为终态。审核必须为授权的 pending 且禁止自审，课程或分类停用时允许拒绝、不允许通过。前端隐藏非法操作，后端仍逐次授权。

401 清理内存会话并引导登录，保存安全的站内返回路径；不得持久化令牌来实现“记住登录”。403 说明操作受限；404 不暴露对象；409 保留审核意见等输入，提示数据已变化并刷新详情，不自动重放写请求；422 关联字段错误并聚焦首个错误；503/网络失败提供手动重试。Toast 只补充反馈，关键错误在内容区域持续可见。

写入期间禁用同一对象操作。成功后用服务端响应更新状态/版本，并使相关列表、通知和指标缓存失效；失败保留输入。收藏可乐观更新但失败必须回滚，连点合并或禁用到请求结束；审核、撤回、归档不做乐观成功。

### 5.3 API 对齐规则

- 统一由 `src/api/` 客户端解析 `data/request_id/error`；组件只接收类型化数据与事件，不直接散落请求。
- 列表默认每页 20；资源中心可提供 20/40，管理表格 20/50/100；最大 100。总数来自服务端 `total`，不可取当前页 `items.length` 代替。
- 日期由 API UTC 转浏览器本地时区，显示时注明时区或在 Tooltip 显示完整时间；演示日期不沿用图片中的 2024 年作为当前数据。
- 搜索仅按标题 `q`，最长 100 字符，去空白后为空则不传；不是全文、老师或课程名搜索。中文输入法 composition 结束后再触发请求。
- 资源目录仅支持 `q/course_id/category_id/resource_type/sort/page/page_size`；排序仅 newest/title。不得发送标签、多选数组、热度、相关度或时间范围等未定义参数。
- 课程/分类筛选字典必须处理分页；按需加载或逐页获取有界数据，不假定第一页就是全部。
- 收藏和学习记录的 `resource.unavailable=true` 时，只显示“资源暂不可用”与允许操作；不从旧缓存补出标题/URL，取消收藏仍可用。
- 不为装饰头像发起 N+1 用户查询。DTO 无人员显示名时显示“用户 #ID”或省略；审核人同理。禁止向非管理员调用 `/users` 来补全名称。
- Resource 没有 `submitted_at`；表格首版显示并标注“创建时间”或“更新时间”，不能把 `created_at/updated_at` 改名为准确提交时间。若未来必须展示最近提交时间，应先补契约；通知/审核时间使用各自记录的 `created_at`。

## 6. 页面 A：学生首页（第 2 版）

- 精选区域最多同时展示 1 个主卡，附 3–4 个手动切换指示器；无精选配置时展示最新已授权资源，不随机轮换。不能把当前登录用户的数据用于其他账户。

- 缺封面用按 document/video/link 类型区分的默认图案；插画加载失败降级为浅蓝装饰背景，文字和搜索始终可用。

### 6.3 交互与动效

- 搜索 Enter/按钮提交到 `/resources?q=...`；关键词为空时进入资源中心。未登录先引导登录再恢复站内搜索条件。
- 课程快捷项传 `course_id`，主卡标题进入资源详情；继续学习先进入详情，再由明确的“打开外部资源”按钮打开链接，不自动打开窗口或写入 100% 进度。
- 手动轮播支持左右按钮、键盘和触屏；默认不自动播放，指示器带序号与名称。首版可简化为单张主卡，不为动画新增依赖。
- Bento 可交互卡 hover 上移最多 2 px、阴影轻增，180 ms；只有真实可点击卡片呈现指针。Hero 插画不做持续漂浮、鼠标追随或视差；首屏可有一次 220 ms 的淡入。

### 6.4 响应式

平板 Hero 降至 260–300 px、插画收为右侧淡背景；Bento 改 2 列，精选可跨 2 列，后续每块自然排布。移动 Hero 高度随内容增长、插画缩成标题下方小图或隐藏；搜索通栏，课程项换行，最多首显 4 个再“更多”。Bento 全部单列，顺序为精选、继续学习、课程探索、收藏/最新资源；无固定跨行空洞。任何卡片不可为了保持截图比例截断正文或操作。

- 桌面筛选单选后立即刷新并回到第 1 页；文本搜索可 300 ms 防抖，Enter/按钮立即执行。取消旧请求或忽略过期响应，避免慢响应覆盖新筛选。

### 8.2 真实数据与业务边界

- 本人最近资源来自 `/resources/mine`；四指标可通过相应状态查询的 `total` 获取，或未来明确统计接口，不将第一页按状态计数当总数。

- 最近审核结果优先用本人审核通知列表；通知列表需按需继续分页后再筛 kind，不能只筛第一页并声称完整。资源级完整意见通过授权的 `/resources/{id}/reviews` 获取；没有跨资源审核聚合接口时不并发遍历所有资源来拼全量结果。
- 已发布资源不能直接编辑；菜单提供“查看/撤回”等合法动作。驳回条目突出“查看意见”，本人可据意见修改后重新提交。

### 8.3 交互与状态

指标点击跳本人资源对应状态列表（目标页已实现时启用）；最近资源菜单可键盘打开；审核意见抽屉保留完整纯文本。通知仅在标记已读接口成功后更新已读状态；未实现通知汇总时不虚构红点计数。

首次无资源显示共享引导；无审核结果显示“提交审核后将在这里收到结果”；数据区独立加载和失败，四指标失败显示“—”及重试。版本冲突保留表单/意见并刷新；操作成功后同步最近资源、统计及结果区域，不盲目整页刷新。

### 8.4 动效与响应式

常规 hover/focus 120–180 ms，抽屉 200 ms；指标数字直接显示，无滚动计数。图表如已接入，首次最多 300 ms 绘制，切换时间保留高度并显示局部加载。

平板侧栏为抽屉、指标 2×2、双列表上下排列；移动欢迎横幅改纯文字小卡、按钮通栏，指标仍 2×2（标签允许换行），最近资源改摘要行+“详情/更多”菜单。表格所有操作在移动仍可访问，完整元数据放详情抽屉；不直接删掉状态与审核意见入口。

## 9. 页面 D：管理员后台（第 6 版）

管理端优先保留信息与操作，装饰只占很小比例；不得添加学生首页式大 Hero 或巨幅插画。表格正文 14 px，辅助数据最低 12 px，默认行高约 52–56 px，表头 40 px。

### 9.2 指标与图表契约

待审队列用 `/reviews/pending`，自动排除本人历史资源；管理员资源管理与全站统计没有对应聚合契约，不能把 `/resources` 的公开可见 total 称为“全部资源总数”。用户总数可取 `/users` total；全站访问量、UV、日趋势、分布与环比缺接口，适用第 1.3 节未接入规则。

未来统计接入前先明确：统计范围、计量口径、更新频率、时区、日期边界、缺失日期、比较基期与零分母。空图显示“此范围暂无数据”，缺测点留断点，不自动补 0；没有分母时显示“—”，不能生成无限增长。

趋势图使用品牌蓝主线、次线用青色/虚线，背景仅浅网格；Tooltip 提供完整日期与各序列数值，键盘/触屏可获得同等信息。环图配文字图例、数量和百分比；0 条时不用整圈假占比；长类别名可换行。每个图表提供文字摘要或等效数据表。

### 9.3 审核交互与状态

- 命令面板可由按钮、Windows/Linux 的 Ctrl+K 或 macOS 的 Cmd+K 唤起；可搜索已有菜单项，Enter 执行导航、Esc 关闭并恢复焦点。输入框内不注册单字母全局快捷键；快捷键不可作为唯一操作入口。
- 行主操作“审核”打开详情抽屉/审核页，先展示元数据、外链域名、类型、课程分类、版本和历史；没有系统内容扫描接口，不显示“格式校验/内容安全/查重已通过”。
- “通过”与“驳回”在详情内明确分开；驳回必须填写去空白后非空且最长 2000 字意见，通过意见可选。提交必须携带已读 `expected_version`，不允许仅凭表格摘要盲审。
- 外部内容预览仅在另行支持时启用；首版使用明确的打开外链动作，不默认嵌入第三方 iframe，不向后端请求抓取链接。
- 提交前确认资源名、决定和意见；提交中禁用重复动作。成功后移出队列、刷新 total/相关指标，焦点移到下一条或表头并播报结果。
- 409 提示“此资源已发生变化，请刷新后重新审核”，保留意见，刷新后要求重新审阅并主动提交；禁止自动重试/自动通过下一条。
- 本人资源显示“不可审核本人资源”而非可提交按钮；课程/分类停用时说明不能通过的原因，保留拒绝能力。
- 当前没有批量审核接口，不显示批量通过/驳回按钮或误导性全选。未来批量能力需明确每项版本、授权、部分失败结果，重新审定后实施。
- “删除”统一按业务含义改为归档/停用；归档需原因与不可恢复说明，不能调用不存在的硬删除 API。

### 9.4 动效、空状态与响应式

侧栏折叠宽度切换 180 ms，表格只使用淡背景反馈，不为行移除播放大型布局动画。图表初始化最多 300 ms，工具条交互 120–160 ms，reduced-motion 时禁用位移/绘制动画。

待审为空显示“当前没有待审核资源”，保留管理导航；表格失败与图表失败独立，不用空队列掩盖请求失败。待审编号和数量可变化，操作后服务端为准，不假设一定减 1。

平板侧栏抽屉、指标 2×2、图表上下堆叠；移动顶部只留菜单、标题、通知和账户，搜索由图标唤起，日期单独一行。待审表格在移动改摘要列表，保留标题、类型、创建时间、状态和审核按钮，其他字段在详情显示；需要完整表格时提供单独横滚容器与文字提示。抽屉在窄屏全宽，审核操作固定底部并留安全区，意见区不被遮挡。

## 11. Nuxt UI 与技术实现约束

### 11.1 集成边界

技术栈固定为 **Vue 3 + TypeScript + Vite + Vue Router + Nuxt UI，后端 FastAPI**。Nuxt UI 是组件库，本项目不是 Nuxt 应用。

实施时核实 package/lockfile、Node engine 和 peer dependency。无工程时采用经过验证的兼容版本并记录，不仅写“latest”。截至本次查阅官方 v4 文档，独立 Vue 通过 Vite 插件和 Vue 插件接入；沿用 architecture.md 的集成步骤，注册 `@nuxt/ui/vite` 与 `@nuxt/ui/vue-plugin`，入口导入 Tailwind 与 Nuxt UI CSS，根使用 `UApp` 和隔离层。自动声明与主题别名依安装版本配置，干净环境先生成声明再类型检查。依据：[官方 Vue 安装源文档](https://raw.githubusercontent.com/nuxt/ui/v4/docs/content/docs/1.getting-started/2.installation/2.vue.md)。

不创建 `nuxt.config.ts`、Nuxt `server/`、`defineNuxtConfig`、`useFetch` 等 Nuxt 专属运行依赖。页面显式注册 Vue Router；后台请求经现有 API 客户端；不把 FastAPI 迁移进前端框架。

### 11.2 主题与组件选择

- 将 `--lh-*` 令牌映射到实际版本的 primary、text、background、border 和 focus 语义；默认实心 primary 必须得到精确 `#004CFF`，不能只选预置 blue 后接受近似色。
- hover/active、soft、outline 分别验证；使用库的主题配置和 `ui`/slot 定制，避免大量深层 CSS、`!important` 和 DOM 选择器覆盖。
- 首版以浅色为唯一验收主题；无完整暗色设计时不显示主题切换，也不因系统暗色让页面自动变黑。
- 组件 API 先查当前类型/文档再用，不能混用 v2/v3/v4 的属性、插槽和表格写法。新增依赖仅在确实缺功能且体积合理时使用。

| 需求 | 优先组件/方式 |
| --- | --- |
| 按钮、输入、表单 | `UButton`、`UInput`、`UForm`、`UFormField` |
| 筛选、分段、标签 | `USelect`/`USelectMenu`、`URadioGroup`、`UCheckbox`、`UTabs`、`UBadge` |
| 内容与反馈 | `UCard`、`USkeleton`、`UProgress`、`UAlert`、`UToast`/库的 Toast API |
| 导航与个人菜单 | `UNavigationMenu`、`UDropdownMenu`、`UAvatar`、`UTooltip` |
| 弹层与管理表格 | `UModal`、`USlideover`、`UTable`、`UPagination` |
| Dashboard 壳 | 已安装版本支持时使用 `UDashboardGroup`、`UDashboardSidebar`、`UDashboardPanel`、`UDashboardNavbar`/`UDashboardToolbar` |
| Bento / 图表 | CSS Grid；图表单独封装，延迟加载已有轻量方案，不假定 Nuxt UI 自带统计业务 |

Dashboard 组件须先做独立 Vue 的最小运行验证；不能因库名称包含 Nuxt 而换栈。若安装版本缺所需壳组件，使用 Nuxt UI 基础组件与 CSS 实现相同布局并记录差异，不大规模升级或引入第二套组件体系。官方侧栏提供移动弹层模式，可据当前 API 配置抽屉体验，仍须验证焦点与断点；参考 [DashboardSidebar 官方实现](https://github.com/nuxt/ui/blob/v4/src/runtime/components/DashboardSidebar.vue)。

### 11.3 素材约束

四张 PNG 是整页参考，不可作为页面背景来模拟完成 UI，也不把截图切片当按钮/表格。正式品牌图、插画、封面需独立资产且来源/授权明确；没有资产时用 CSS 渐变和类型图标占位。不得为补全图片自动新增生成服务或使用未授权人物照片。固定图片宽高，装饰图 `alt=""`，有内容意义的图片提供简短替代文本；不在图片内承载唯一的信息或动作。

## 12. 无障碍、性能与安全呈现

### 12.1 无障碍验收

- 以 WCAG 2.2 AA 为目标：正文对比度至少 4.5:1，大字至少 3:1，必要非文本 UI 与焦点至少 3:1；逐状态检查而非只测默认态。大字指约 24 CSS px 的常规字或约 18.7 CSS px 的粗体字；参照 [W3C WCAG 2.2 检查指南](https://www.w3.org/WAI/WCAG22/quickref/)。
- 全部任务可只用键盘完成；有跳至主内容链接、landmark、逻辑标题、可见焦点，无焦点陷阱。列表/表格使用真实语义，表头可关联单元格。
- 表单有可见 label、必要说明、必填标识；错误用 `aria-describedby` 关联，不能只在 Toast 中出现。Placeholder 不能替代 label。
- 所有图标按钮有名称，选中/展开态有相应 ARIA；资源状态同时用文字；进度条提供名称与当前值。
- 列表更新/收藏/审核结果用适度的 `aria-live="polite"`；不持续播报图表每个动画帧。错误重点可用 alert，避免重复播报。
- 系统 `prefers-reduced-motion: reduce` 下取消位移、轮播过渡、图表绘制和 Skeleton 闪动，以静态状态代替；功能与反馈不能消失。
- 200% 缩放仍可完成任务，320 px 宽下正文不双向滚动；表格/图表仅允许局部横滚。触控目标优先 44 px，符合移动操作需要。
- 页面声明 `lang="zh-CN"`；帮助文本与按钮名称一致，焦点不被 sticky 顶栏或底部操作条遮挡。登录允许粘贴密码、密码管理器与浏览器自动填充，不要求记忆型验证题。

### 12.2 性能目标与测量

以下为后续实施目标，不是本次已经测得的数据：

- 有真实用户数据时以第 75 百分位 LCP≤2.5 s、INP≤200 ms、CLS≤0.1 为目标，移动/桌面分别统计；阈值依据 [Google Core Web Vitals](https://web.dev/articles/vitals)。上线前用生产构建和记录清楚的设备/网络条件做实验室检查，不把 Lighthouse 单次分数等同真实用户指标。
- 四页按路由懒加载，图表按需导入；首页不加载管理员图表或完整表格依赖。不为一次淡入引入大型动画库。
- 首页首屏插画目标≤250 KB，普通缩略图目标≤60 KB，优先 WebP/AVIF 与合适分辨率；LCP 图优先加载，折叠线以下图片懒加载并预留比例。若达不到目标，记录原因与优化结果。
- 初始路由压缩后 JS（含其同步共享依赖）目标≤250 KB gzip，超出先分析体积；资产预算不得以降低可访问性或去掉必需业务换取。
- 服务端分页与有界缓存优先；不拉取全表作统计/筛选，不逐卡请求人员/资源详情。请求去重并处理竞态，切换账户清理个人缓存。
- 不做持续轮询来制造“实时”，通知/指标刷新频率随真实业务确定；同页重复数据可复用，失败必须可恢复。

### 12.3 安全呈现

标题、描述和审核意见按纯文本渲染，不直接 `v-html`。外链只按契约接受 HTTPS，打开时隔离 opener，界面明确外部来源；不自动抓取、嵌入或下载外链内容。错误仅显示安全消息与 request_id；前端不能持有服务端密钥，也不能通过隐藏按钮代替后端授权。
